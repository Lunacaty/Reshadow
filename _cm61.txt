feat(204 A 方案): DIY 第 ③ 端从旧脚本效果块换成 PyAST 规范语法

按 A 方案直接替换，JSON / 旧脚本端下线。

【现状梳理】
  ③ 端原本叫「AST 语法树端」，但实际跑的是 ReshadowScriptCompiler.PrintEffectOnly
  —— 它产出的既不是 JSON，也不是规范 AST，而是手写的文本版 AST（Fanfare: / Deal 3 ...）。
  真正走 AstJsonCodec 的 JSON 路径只存在于注释和少数兼容分支里。

【改动】
  · DiyWorkshopController.CompileFromCanonicalAst(dsl)
      用 AstCanonicalParser.ParseAbilities 解析效果块（纯能力列表，无卡头），
      卡名/费用/身材沿用当前卡。
  · SyncAllEndpointsFromCurrentDef
      AstJsonText 改为 AstCanonicalPrinter.PrintAbilities 的输出。
  · DiyWorkshopView 页签改名「③ AST 规范语法」，
      13 个模板按钮全部换成真实 PyAST 语法：
        fanfare: / last_words: / evolve: / super_evolve: / aura:
        draw 2 / buff $self +2/+2 / grant_keyword ward to $self
        select opponent:board Choose(1) where is Follower
        if ctr:pp_at_play >= 7: ... else: ...
        modes Choose(pick=1): option 1: ... option 2: ...
        summon 1 "Fairy"
        grant_ability to $self: last_words: draw 1

【顺带修好 ParseAbilities 的一个能力缺口】
  效果块允许「只写动作、不写触发头」（DIY 的 ③ 端正是这种形态），
  但 ParseAbilities 原先只认触发头，遇到 draw 2 / buff ... 会报「未知的触发头」。
  现已支持：当前词不是触发头时，把后续语句整包成一条无触发头的能力。
  新增 IsTriggerHeaderWord 判据。

验证：13 个模板逐个解析，全部 能力数=1 且零错误。
